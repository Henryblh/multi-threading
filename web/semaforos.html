TRABALHO PRÁTICO 3 / SEMÁFOROS / SEÇÃO CRÍTICA

Canal de
Rádio

Cada thread é um operador de rádio com uma mensagem própria. O canal só entende uma voz por vez, como um walkie-talkie. O que acontece quando todos falam juntos? E quando um semáforo dá a vez?

Os três conceitos

Recurso compartilhado: o canal de rádio.
Seção crítica: transmitir a mensagem inteira.
Semáforo: a permissão para falar. acquire() pede; release() devolve.

01

Configure o canal

Uma linha por operador (de 2 a 6). Cada linha vira uma thread.

Frequências (permissões do semáforo)
Com 1 permissão o semáforo é binário (um mutex). Com 2 ou mais, até N operadores falam ao mesmo tempo, cada um na sua frequência.

As duas transmissões usam as mesmas mensagens e os mesmos tempos por palavra.

02

No ar

Faixa listrada: esperando o semáforo. Faixa cheia: com o canal (dentro da seção crítica). Cada traço é uma palavra transmitida.

SEM CONTROLE

Todos falam quando querem

Aguardando transmissão.

COM CONTROLE

Fala quem tem a permissão

Aguardando transmissão.

03

O código que muda

Versão resumida de java/CanalDeRadio.java. A única diferença entre os dois lados é pedir e devolver a permissão.

MENSAGENS MISTURADAS

Sem controle, as palavras de vários operadores se intercalam no canal. Todas chegam, mas nenhuma frase fica legível.

ATUALIZAÇÃO PERDIDA

"contador + 1" é ler, somar e gravar. Se duas threads leem o mesmo valor, uma gravação apaga a outra e o total fica menor que o esperado.

O PREÇO DO CONTROLE

O semáforo garante a integridade, não a velocidade: enquanto um fala, os outros esperam. Mais permissões, menos espera.

Nota de método. O tempo de cada palavra é simulado com uma pausa. Em Python o GIL deixa x += 1 quase atômico, então a pausa entre ler e gravar o contador alarga a janela da condição de corrida para ela aparecer numa demonstração curta. O programa Java em java/CanalDeRadio.java faz o mesmo experimento no terminal.
