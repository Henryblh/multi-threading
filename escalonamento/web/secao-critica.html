Laboratório da
Seção Crítica

Cada mensagem primeiro é digitada num rascunho local, fora da seção crítica. Depois é publicada: lê o próximo número livre, escreve no histórico e grava o número seguinte. Se o escalonador tirar a CPU no meio da publicação, duas mensagens leem o mesmo número. Isso é condição de corrida, mesmo com uma CPU só. O semáforo protege só a publicação; o resto continua no rodízio.

        Nota de método. Cada mensagem é uma Thread Java real executando o código acima sobre memória compartilhada de verdade. O despachante concede um passo por vez e decide onde trocar de thread, então a mesma entrada sempre gera o mesmo erro, no mesmo tick. O semáforo é o de Dijkstra (contador + fila de bloqueados), simulado pelo despachante para que dê para vê-lo por dentro. Para o erro com threads livres e não determinístico, veja o CanalDeRadio.java da branch feat/semaforos-tp3.
